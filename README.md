# 128 位 Karatsuba 乘法器

用 Verilog 写的 128 位 Karatsuba 乘法器，输出 256 位完整乘积。设计目标是省面积：整个电路里只有一个基乘单元和一个加减器，让它们轮流干活。

A 128×128-bit Karatsuba multiplier in Verilog, producing the full 256-bit product. Area-first: one base multiplier and one add/sub unit, time-multiplexed.

---

## 一、设计概况

| 项目 | 内容 |
|---|---|
| 功能 | 128 位 × 128 位，输出 256 位完整乘积 |
| 算法 | 两级 Karatsuba，128 → 64 → 32 |
| 基乘单元 | 1 个，34×34 移位相加 |
| 加减器 | 1 个，261 位，加减共用 |
| 基乘次数 | 9 次 |
| 控制方式 | 微码状态机，18 位 one-hot 操作码 |
| 流水 | 三级（PH_SEL / PH_ADD / PH_WRITE） |
| 单次运算周期数 | 443 拍（仿真测得） |
| 语言 | Verilog-2001，纯 RTL，没有厂商原语 |

## 二、算法

### 第一级：128 位拆成 64 位

```
x = a1·2^64 + a0        y = b1·2^64 + b0

w0f = a0 · b0
w2f = a1 · b1
wpz = (a1 + a0) · (b1 + b0)
z1  = wpz − w0f − w2f

y   = w0f + (z1 << 64) + (w2f << 128)
```

普通乘法要 4 次子乘法，Karatsuba 只要 3 次，代价是多几次加减。

### 第二级：64 位拆成 32 位

第一级算出来的三路上界 w0f、w2f、wpz 都是 64×64，再各拆一次，每路 3 次基乘，总共 9 次。以 w0f = a0·b0 为例：

```
a0 = A1·2^32 + A0        b0 = B1·2^32 + B0

s0   = A0 · B0
s2   = A1 · B1
M    = (A0 + A1) · (B0 + B1)
xsum = s0 + s2·2^32
s1   = M − xsum

w0f  = xsum + s1·2^32          （等于 s0 + s1·2^32 + s2·2^64）
```

三层加减全部交给同一个 261 位加减器，按补码算，不需要单独处理符号。

### 位宽是怎么定的

几个关键位宽不是随便取的，都是从范围推出来的：

| 寄存器 | 位宽 | 为什么 |
|---|---|---|
| a01 / b01 | 65 | 两个 64 位数相加，最高位可能进位 |
| EFs / FFs | 34 | a01 的高半是 33 位，两个 33 位数相加要 34 位 |
| mult_op_a / b | 34 | 要装下 EFs / FFs，33 位会截断 |
| 基乘结果 m0–m8 | 68 | 34×34 最大 68 位 |
| midsum | 100 | s0 + (s1<<32) 最多 98 位，多留 2 位 |
| wpz / z1 / z1_0 | 130 | xsum + (s1<<32) 最多 129 位，留 1 位放借位 |
| 加减器 UW | 261 | 最大的一次运算是 `y = w0f + (z1<<64) + (w2f<<128)`，结果 256 位；取 261 位是为了装下补码减法产生的借位和符号扩展，留了 5 位余量 |

如果基乘单元只做 32 位，33×33 的结果会被截断，这是必须取 34 位的原因。

## 四、模块与接口

### karatsuba128 —— 顶层核心

内部有微码状态机、基乘调度器、261 位加减器的操作数选择、三级流水控制。

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| clk | 输入 | 1 | 时钟 |
| rst_n | 输入 | 1 | 异步复位，低有效 |
| start | 输入 | 1 | 上升沿启动一次运算 |
| a | 输入 | 128 | 被乘数 |
| b | 输入 | 128 | 乘数 |
| busy | 输出 | 1 | 运算中为 1 |
| done | 输出 | 1 | 运算完成时高 1 拍 |
| y | 输出 | 256 | 乘积 |

### mult_base —— 基乘单元

参数化位宽 `W`，顶层例化时 `W = 34`，乘积 `2W = 68` 位。内部是逐位移位相加。

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| clk / rst_n | 输入 | 1 | 时钟、异步复位（低有效） |
| start | 输入 | 1 | 上升沿重新装载并开始 |
| a / b | 输入 | W | 两个操作数 |
| busy | 输出 | 1 | 运算中为 1 |
| done | 输出 | 1 | 完成时高 1 拍 |
| result_rdy | 输出 | 1 | 完成后一直为 1，直到下次 start |
| ack | 输入 | 1 | 留着兼容用，内部没有使用 |
| p | 输出 | 2W | 乘积 |

接口约定：

- `start` 来一个上升沿，重新装载 a/b，从零开始算
- 算的时候 `busy = 1`，第 `W+1` 拍出结果，`done` 只高 1 拍，同一拍 `p` 有效
- 之后 `p` 一直保持，直到下一次 `start` 上升沿

**为什么把 ack 去掉**：原来的设计里 ack 由上层锁存信号产生，而锁存又依赖完成信号，两者互相依赖形成自锁。实际测出来第二次运算开始就锁到上一次的残留值。改成单向协议后问题消失，ack 端口留着只是为了接口兼容。

### addsub —— 加减器

| 端口 | 方向 | 位宽 | 说明 |
|---|---|---|---|
| op | 输入 | 1 | 0 做加法，1 做减法 |
| x / y | 输入 | WD | 操作数 |
| s | 输出 | WD | 结果 |

纯组合逻辑，顶层例化时 `WD = 261`。减法按无符号补码算，借位不单独输出，靠调用方给足够宽的寄存器装。

### karatsuba_top —— FPGA 接口封装

把 128 位输入拆成 8 个 32 位字串行送入，输出也分 8 个 32 位字送出。因为 FPGA 器件引脚不够，裸核有 517 个端口。

| 端口 | 方向 | 说明 |
|---|---|---|
| clk / rst_n | 输入 | 时钟、复位 |
| in_valid | 输入 | 送数据时拉高 1 拍 |
| in_data | 输入 | 32 位数据 |
| in_ready | 输出 | 可以接收数据 |
| out_valid | 输出 | 输出有效，持续 8 拍 |
| out_data | 输出 | 32 位数据 |
| busy / done | 输出 | 状态 |

送数和收数的顺序都是 **高位在前**：a[127:96] → a[95:64] → a[63:32] → a[31:0] → b[127:96] → … → b[31:0]。输出同理，y[255:224] 先出。

ASIC 流程直接用 `karatsuba128` 做顶层，不用这个文件。

## 五、控制流程

### 主状态机

```
S_IDLE --start 上升沿--> S_START --> S_RUN --写回 y--> S_DONE
                          ^                              |
                          +----------- start ------------+
```

| 状态 | 作用 |
|---|---|
| S_IDLE | 等 start |
| S_START | 清空所有中间量和流水寄存器，然后进 S_RUN |
| S_RUN | 按微码一节一节执行，写回 y 之后进 S_DONE |
| S_DONE | done 拉高，等 start 重新开始 |

`S_START` 那个状态就是为了清中间量加的。漏清任何一个，上一轮的值就会参与本轮运算，表现是"单次算对，批量回归大面积出错"。

`S_DONE` 里判断重新启动用的是 `start` 的电平，不是 `start && !start_ff` 的边沿。原因是 S_DONE 是保持状态，测试台在 negedge 拉高 start 时，到下一个 posedge 采样，`start_ff` 已经被这一拍更新成 1，边沿条件会被吃掉，没法重启。用电平判断不会重复启动，因为 S_DONE 只消费一次 start 就进 S_RUN，而 S_RUN 不看 start。

### 三级流水

每条微指令拆成三拍：

| 相 | 做什么 | 路径 |
|---|---|---|
| PH_SEL | `op_oh` → 操作数选择 → `op_a_reg` / `op_b_reg`，同时记住目的 | 控制位独占一拍 |
| PH_ADD | `op_a_reg` / `op_b_reg` → 261 位加减 → `sum_pipe` | 加减器独占一拍 |
| PH_WRITE | `sum_pipe` → 目的寄存器 | 寄存器到寄存器 |

拆三段的原因是原来把"控制译码 + 261 位加减 + 写回选择"全压在一个周期里，组合路径太长。拆开之后控制位只驱动第一相，加减器只用寄存器里的操作数，写回是纯寄存器直连。

流水寄存器一共有：`phase`、`op_a_reg`、`op_b_reg`、`sub_reg`、`sum_pipe`、`sum_vld`、`dst_sel`、`dst_pipe`。

`dst_pipe` 必须在 `S_START` 里清零，因为 `PH_WRITE` 靠 `dst_pipe[17]` 判断 y 写没写完。如果留着上一轮的值，新一次运算第一拍就会误判"已经完了"直接收尾。

### 微码操作码

18 位 one-hot，存在寄存器 `op_oh` 里，不参与组合译码链。

| 操作码 | 位 | 作用 |
|---|---|---|
| OP_LOAD | 0 | 存 a/b，同时算出所有拆分操作数 |
| OP_MMUL | 1 | 基乘段，调度器把 9 次乘法做完 |
| OP_w0_s1a | 2 | `s1_w0 = m2 − m0` |
| OP_w0_s1b | 3 | `s1_w0 = s1_w0 − m1` |
| OP_w0_mid | 4 | `midsum_w0 = m0 + (s1_w0 << 32)` |
| OP_w0_f | 5 | `w0f = midsum_w0 + (m1 << 64)` |
| OP_w2_s1a | 6 | w2f 路，用 m5 / m3 / m4 |
| OP_w2_s1b | 7 | |
| OP_w2_mid | 8 | |
| OP_w2_f | 9 | |
| OP_zp_s1a | 10 | wpz 路，用 m8 / m6 / m7 |
| OP_zp_s1b | 11 | |
| OP_zp_mid | 12 | |
| OP_zp_f | 13 | |
| OP_z1_0 | 14 | `z1_0 = wpz − w0f` |
| OP_z1 | 15 | `z1 = z1_0 − w2f` |
| OP_NOP | 16 | 空操作，给 z1 一点时间 |
| OP_y | 17 | `y = w0f + (z1<<64) + (w2f<<128)`，写回后 done |

执行顺序是 0 → 1 → 2 → 3 → … → 17。`OP_z1_0` 后面必须跟 `OP_z1`，中间不能插别的。

### 基乘调度

基乘要花多少拍是固定的（实测第 33 拍出结果），所以不用动态握手，用一个小的状态机加计数器驱动：

| 状态 | 作用 |
|---|---|
| M_IDLE | 判断要不要启动一次基乘 |
| M_SETUP | 等一拍，让 `mul_k` 换过之后的操作数稳定 |
| M_RUN | 发一拍 start，等基乘完成，存 `base_p`，然后 `mul_k` 加 1 |

`mul_k` 从 0 数到 9，等于 9 时表示 9 次都做完了。

9 组操作数在整个窗口里保持不变，基单元不会拿到下一组的值。

调度器有三个地方容易出问题，代码里都加了注释：

1. **必须在 MMUL 阶段才工作**（`mul_en`）。否则复位后 `mstate` 就是 M_IDLE，`base_start` 立刻变高，基单元会拿还没存进去的 `a_i`/`b_i`（全是 0）去做第一次乘法。
2. **`M_SETUP` 必须无条件进 `M_RUN`**。加了流水之后 `mul_en` 只在 PH_SEL 是 1，如果 M_SETUP 里再判一次 `mul_en`，会马上退回 M_IDLE，基乘永远启动不了。
3. **`base_start` 必须是一个单拍脉冲**（用 `base_start_r` 产生），不能从 `mul_en` 直接派生，否则同样死锁。

另外 `mul_latch` 用的是 `base_done` 打一拍之后的 `base_done_d`。因为基单元在 `base_done` 拉高的那个时钟沿同时更新 `p_r`，晚一拍再存才不会存到旧值。

## 六、操作数拆分与 9 次基乘

### 拆出来的操作数

第一级和第二级的拆分全部在组合逻辑里一次算好，`OP_LOAD` 时锁存 `a_i` / `b_i`，之后这些值一直不变，所以可以直接从寄存器上取。

| 名字 | 来源 | 位宽 |
|---|---|---|
| A0, A1 | a0[31:0], a0[63:32] | 32 |
| B0, B1 | b0[31:0], b0[63:32] | 32 |
| C0, C1 | a1[31:0], a1[63:32] | 32 |
| D0, D1 | b1[31:0], b1[63:32] | 32 |
| E0, E1 | a01[31:0], a01[64:32] | 32 / 33 |
| F0, F1 | b01[31:0], b01[64:32] | 32 / 33 |
| ABs, BBs | A0+A1, B0+B1 | 33 |
| CDs, DDs | C0+C1, D0+D1 | 33 |
| EFs, FFs | E0+E1, F0+F1 | 34 |

### 9 次基乘的对应关系

`mul_k` 的值决定用哪一组操作数，结果存进对应的槽位：

| mul_k | 操作数 A | 操作数 B | 结果槽位 | 属于哪一路 |
|---|---|---|---|---|
| 0 | A0 | B0 | m0 | w0f 路的 s0 |
| 1 | A1 | B1 | m1 | w0f 路的 s2 |
| 2 | ABs | BBs | m2 | w0f 路的 M |
| 3 | C0 | D0 | m3 | w2f 路的 s0 |
| 4 | C1 | D1 | m4 | w2f 路的 s2 |
| 5 | CDs | DDs | m5 | w2f 路的 M |
| 6 | E0 | F0 | m6 | wpz 路的 s0 |
| 7 | E1 | F1 | m7 | wpz 路的 s2 |
| 8 | EFs | FFs | m8 | wpz 路的 M |

槽位名字和后来装配时的对应关系：w0f 路用 m0/m1/m2，w2f 路用 m3/m4/m5，wpz 路用 m6/m7/m8。

### 装配阶段的操作数选择

微码每条指令用 `add_x`、`add_y`、`do_sub` 三个信号告诉加减器做什么。这部分的组合逻辑在 `case (1'b1)` 里按 one-hot 展开。

## 七、验证

仿真工具 ModelSim。四个测试平台，参考值都用 Verilog 自带的 `*` 运算符算，和被测电路的实现完全独立。

| 验证项 | 测试平台 | 测了什么 | 结果 |
|---|---|---|---|
| 基乘单元自检 | tb_mult_base.v | 41 组定向 + 2000 组随机 32×32 乘法，同时查 busy 周期数是不是 W+1=33 | 2041 / 2041 通过 |
| 顶层向量回归 | tb_min2.v | 1147 组 128 位向量，比对 256 位乘积 | 1147 / 1147 通过 |
| 边界用例与周期数 | tb_cyc.v | 0×0、1×1、最大×最大 | 3 / 3 正确，均为 443 拍 |
| 基乘单元时序标定 | tb_align2.v | 逐拍看 state/cnt/p_r/done/result_rdy | 第 33 拍 p_r 有效，done 同拍拉高 |

### tb_mult_base 测什么

- 定向向量：0、1、最大值、2^31、交替模式 `0xAAAAAAAA` / `0x55555555`，再加 32 位单比特遍历
- 随机向量：2000 组，用 `$random` 生成
- 除了比对乘积，还数 `busy` 持续多少拍。这个基乘单元是固定延迟，周期数不对说明时序有问题，和结果对不对是两件事

### tb_min2 怎么跑

读同目录下的 `sweep_in.txt`，每行两个 32 位十六进制数（a 和 b），逐条施加激励，等 `done` 后比对 `y`。

时序上有一点要注意：**先在 negedge 把操作数摆好，再在下一个 negedge 发 start**。如果操作数和 start 同一拍给出，RTL 可能在操作数稳定之前就采到 start。这也是为什么 `S_DONE` 里用 start 的电平判断而不是边沿。

### 复现步骤

```bash
# 编译
vlib work
vlog -sv RTL/RTL设计代码/mult_base.v \
        RTL/RTL设计代码/addsub.v \
        RTL/RTL设计代码/karatsuba128.v
vlog -sv TB/tb_mult_base.v TB/tb_min2.v TB/tb_cyc.v TB/tb_align2.v

# 逐项跑
vsim -c -novopt work.tb_mult_base -do "run -all; quit -f"
vsim -c -novopt work.tb_min2      -do "run -all; quit -f"
vsim -c -novopt work.tb_cyc       -do "run -all; quit -f"
vsim -c -novopt work.tb_align2    -do "run -all; quit -f"
```

用 ModelSim 老版本时 `-novopt` 必须加，否则内部信号被优化掉，`tb_align2` 里那些 `dut.p_r` 之类的层次引用就看不到了。

`tb_min2.v` 读的是相对路径 `sweep_in.txt`，在哪个目录启动 vsim 就在哪个目录找。建议在 `TB` 目录里跑，或者把 `sweep_in.txt` 一起带过去。

## 八、约束文件

`RTL/时序约束与配置/` 里是四个配置文件，分开写是因为两条流程的时钟周期不一样。

| 文件 | 用于 | 时钟周期 |
|---|---|---|
| karatsuba.sdc | FPGA（Gowin）流程 | 24.591 ns |
| pnr.sdc | ASIC 布局布线 | 52 ns |
| signoff.sdc | ASIC 签核 | 52 ns |
| config_openlane.json | OpenLane 流程配置 | — |

`config_openlane.json` 里的关键项：

```json
"DESIGN_NAME": "karatsuba128"
"CLOCK_PERIOD": 52
"STD_CELL_LIBRARY": "sky130_fd_sc_hd"
"FP_CORE_UTIL": 35
"PNR_SDC_FILE": "dir::src/pnr.sdc"
"SIGNOFF_SDC_FILE": "dir::src/signoff.sdc"
"RUN_HEURISTIC_DIODE_INSERTION": true
"RUN_ANTENNA_REPAIR": true
```

注意 `VERILOG_FILES` 里只列了三个文件（`karatsuba128.v`、`mult_base.v`、`addsub.v`），没有 `karatsuba_top.v`。因为 ASIC 流程用裸核做顶层，那个串行接口封装用不上。

三个 SDC 的约束内容都是一样的，只有周期不同：输入 `a`、`b`、`start` 延迟 0，输出 `y`、`busy`、`done` 延迟 0，`rst_n` 设成 false path（异步复位）。

## 九、设计说明与已知问题

### 为什么只用一个基乘单元

全展开的写法要例化 9 个甚至更多乘法器，再加一堆加法器，资源占用会大很多。本设计反过来做：9 次乘法串行做，加减器也只放一个，靠微码调度分时复用。代价是慢（443 拍一次），好处是逻辑少。

哪一边更重要取决于目标平台。如果引脚和逻辑都紧张，这种写法合适；如果只要快，那就该全展开或多级流水并行做。

### 已知问题

- `mult_base` 的 `ack` 端口没有实际作用，保留只是为了接口兼容。如果上层真去连 ack，要自己保证不形成依赖环
- `karatsuba_top.v` 没有单独的测试平台。它是给 FPGA 流程用的串行接口，功能上只是把 8 个 32 位字拼成 128 位再送给核，逻辑很简单，但没有独立验证过
- `tb_align2.v` 里直接引用 `dut.p_r`、`dut.last_it` 这些内部信号，属于白盒测试。换综合后的网表跑不了，只能对着 RTL 跑
- 443 拍这个数是从 `tb_cyc.v` 仿真出来的，不是算出来的。大致构成：基乘单元本身每次 35 拍（W=34 时 W+1），9 次占 315 拍，是大头；剩下的是载入段、调度开销（每次基乘之间要过 M_IDLE / M_SETUP，还要等 PH_SEL 对齐）和装配段 16 条微指令 × 3 拍。如果改了微码条数或者基乘位宽，这个数会变

### 调试时踩过的坑

代码注释里记了几条，这里汇总一下：

1. **基乘槽位错拍**：`base_p` 是基单元 `p_r` 的组合直连，而 `p_r` 和 `base_done` 是同一时钟沿更新的。直接用 `base_done` 当锁存使能会锁到上一次的乘积，要打一拍
2. **调度器没门控**：复位后立刻就开始第一次乘法，用的是还没锁存的全 0 操作数
3. **`mul_k` 不复位**：停在 9，`mul_done` 恒真，第二次运算直接跳过整个 MMUL 段
4. **中间量不清**：`S_START` 不加的话，第二轮用第一轮的残留值，单次测不出来
5. **`dst_pipe` 不清**：新一轮第一拍就误判 y 已经写完，直接收尾
6. **`start` 的电平/边沿**：S_DONE 里必须用电平判断，边沿会被测试台的时序吃掉
